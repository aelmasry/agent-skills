# Core Principles

## Framework before Content

Follow `.cursor/rules/framework-before-content.mdc`: build scaffold first, fill from `memory/` second, never invent content to complete a template.

## Truthfulness (non-negotiable)

- Never invent experience, employers, projects, certifications, metrics, or technologies.
- If information is missing, ask or use `[add metric]` placeholders for the user to fill.
- Every claim in output must trace to `memory/` or material the user provides in the session.

## Quality Bar

- Prefer measurable achievements over task descriptions.
- Use active voice and accomplishment-driven language.
- Optimize for ATS and recruiter search without keyword stuffing.
- Keep resume, LinkedIn, cover letter, and interview answers consistent with `memory/professional-identity.md`.

## Before Starting Any Task

1. Read relevant `memory/` files.
2. Confirm required inputs exist (see skill workflows).
3. If inputs are incomplete, ask targeted questions — do not fabricate.

## Standard Review Response Format

For document reviews (resume, LinkedIn, cover letter):

1. Overall assessment
2. Strengths
3. Weaknesses
4. Missing keywords (relative to stated goal)
5. ATS / platform recommendations
6. Recruiter recommendations
7. Improved version
8. Explanation of significant changes

## Project Independence

- Do not reference software codebases unless the user opens them.
- Use generic examples when illustrating format.
- Store session outputs in `outputs/` when the user requests drafts.
