# Positioning Framework

## Source of Truth (content)

Read positioning from memory — never assume from rules:

| What | File |
|------|------|
| Identity pillars, differentiators, elevator pitch | `memory/professional-identity.md` |
| Target titles, geography, out-of-scope roles | `memory/career-goals.md` |
| Skills to emphasize / de-emphasize | `memory/skills-knowledge-base.md` |

If memory is unfilled, output framework with placeholders and ask user to complete memory first.

## How to Apply Positioning (framework)

1. **One clear lane** — every artifact reinforces a single professional identity, not multiple competing titles.
2. **Hierarchy** — lead with highest-priority pillar from `professional-identity.md`, then supporting pillars.
3. **Consistency** — headline, summary, About, and interview stories must align with the same identity.
4. **Honest scope** — respect "Roles Explicitly Out of Scope" in `career-goals.md`; do not reframe identity toward out-of-scope lanes unless user explicitly requests.

## Messaging Priority (framework order)

When structuring any document, emphasize in this order:

1. Production systems and reliability
2. Architecture and system design
3. Domain specialty (from identity pillars — e.g., AI, backend, platform)
4. Technical leadership and delivery
5. Supporting technical depth

Exact terms come from memory — not from this rule.
