# ATS Checklist (quick)

Run before finalizing a tailored CV.

## Layout & parseability

- [ ] Single-column layout recommended
- [ ] Standard headers: Summary, Skills / Core Competencies, Experience, Education, Certifications
- [ ] No tables, text boxes, or graphics for core content
- [ ] No headers/footers with critical contact info only
- [ ] Consistent dates (Month YYYY or MM/YYYY)
- [ ] File format: .docx or text-friendly PDF

## Content

- [ ] Contact + LinkedIn + GitHub (if strong) at top
- [ ] Summary 3–4 lines with target-role keywords (truthful)
- [ ] Skills grouped (AI / Architecture / Backend / Cloud / Leadership) — not a keyword wall
- [ ] Bullets: Action verb + scope + method/tech + outcome
- [ ] Acronyms expanded once: e.g. Retrieval-Augmented Generation (RAG)
- [ ] No photos, icons, or skill bars

## Tailoring to JD

- [ ] Required skills appear in Skills and/or Experience when true
- [ ] Job title language echoed where accurate
- [ ] Matching bullets lead each recent role
- [ ] No invented tools to chase the score

## Before submit

- [ ] Match score reported with max-achievable and gaps
- [ ] Tailored file name clear: e.g. `Ali_Abdulhafez_AI_Engineer_Company.docx`
- [ ] One page preferred for focused mid-senior; two pages OK for deep senior/architect histories
