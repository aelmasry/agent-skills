# Proposal / Outreach Skeleton

Use for **freelance / contract**. For **FT/PT jobs**, do not use this — run `cv-jd-matcher` (CV + cover letter). For **potential clients** with no SOW yet, use the short outreach at the bottom.

Keep proposals short. Senior clients skim.

```markdown
# Proposal: [Project name]

## Understanding
2–4 sentences: restate the problem in your words. Show you understood constraints.

## Approach
Phased plan (Discovery → Design/Build → Harden/Handoff). Name artifacts, not buzzwords.

## Deliverables
- [Concrete output 1]
- [Concrete output 2]
- [Concrete output 3]

## Timeline
Week 1: …
Week 2–N: …
Assumptions: access, SMEs, environments

## Why me
2–3 proof points from real experience (map to master resume / achievements). No hype.

## Engagement & commercial
- Model: fixed / T&M / retainer
- Rate or fee: [user-provided or "to be confirmed after discovery"]
- Payment milestones
- Out of scope (important)

## Next step
15–30 min call to confirm success criteria and access.
```

## Pitch paragraph (LinkedIn / DM)

```
I help [type of company] ship [AI / architecture / backend outcome].
Relevant: [one proof]. Happy to propose a short discovery + fixed-scope phase if useful.
```

## Potential client (no SOW yet)

Do **not** send a full proposal. Send:

1. One-sentence problem observation
2. One relevant proof
3. Ask for a 15–30 min discovery call
4. 3 discovery questions (success criteria, timeline, tech constraints)

## Rules

- Tie every claim to real work
- Prefer phased fixed-scope over open-ended "we'll figure it out"
- Always list out-of-scope to protect rate
- Jobs with a JD → cover letter via `cv-jd-matcher`, not this template
